# 技能与工具按需加载优化（2026-11-28）

## 结果与范围

第二阶段已在本机 Octop 主程序启用。相同模型配置、相同虚构汇总题、均使用新会话，模型输入从 **29,440** 降为 **11,234 tokens**，减少 **61.84%**。实际回答仍只有要求的三条状态，没有调用工具或补写承诺。

这是一次请求的输入量对照，不代表所有任务的质量、延迟或账单都按同一比例改善。缓存命中率不同；分段 token 为估算，渲染顺序变化也会影响分类，不能把分段数直接当精确账单。

不改变 Ask/Plan/Craft 权限边界、MCP 身份与授权、用户工作区文档或业务口径。保留原有账号、聊天、模型配置与记忆。

## 代码归属与实现

运行库源码位于 `独立的 octop-harness 源码检出目录`，基于官方 develop，工作分支为 `codex/progressive-catalog`。改动尚未提交、推送或发布到 PyPI；源码补丁及基线见 `output/progressive-catalog-20261128/harness-source.patch` 和 `owner-source.json`。

- `octop-harness` 增加可选 `progressive_catalog_enabled`，默认关闭，保持库用户的原有行为。Octop 对支持该字段的运行库统一启用；不支持时保留兼容路径。
- 大目录通过 `search_skills` 按名称或中英文关键词返回匹配技能的说明和路径，再走正常 `read_file` 读取。普通问答不展开整个目录；小目录及显式 `/skill` 仍可直接使用。
- 非核心工具复用原 `tool_search` 加载流程，先展示真实名称和精简引用，加载后提供原始完整 schema。文件操作、时间、提问、记忆等核心工具保持直接可用。
- 搜索只索引当次过滤后可见的目录，按会话和执行用户隔离；禁用技能、未选择范围及 Ask/Plan 限制不会因发现工具被恢复。
- 已加载的工具 schema 和技能名称可在同一会话复用。目录元数据仍在服务端扫描和缓存，减少的是送给模型的内容，不是删除技能或省去全部本地读取。
- 本机仍沿用定制的 1.0.7 运行库，仅回移本轮功能与兼容适配，没有整体升级其依赖。旧 deepagents 编排显式保证权限过滤先于技能目录渲染，预算检查和使用量快照继续保留。

主要文件：

- 运行库 `src/octop_harness/middleware/skill_discovery.py`、`middleware/tool_search.py`、`config/__init__.py`、`agent.py`。
- Octop `src/octop/infra/agents/manager.py`：启用支持的目录能力。
- `customization/packages/octop_harness/`：本机运行库的对应回移；`middleware/compaction_order.py` 保留旧编排兼容。

## 本机真实链路验收

安装后 2 个账号、17 个专家保持加载，数据库中的专家状态均为 running。通过原生 Octop 窗口执行四项虚构验收：

1. **普通汇总**：与第一阶段相同的题目，只回答字段核对完成、两项口径差异、历史重算未执行且待确认三条状态，无工具调用。
2. **技能发现**：仅查询关键词 Excel 的两个匹配项，真实调用 `search_skills`，返回 `data-analyst`、`kdocs`；没有通过 read_file 读取技能正文或执行技能。
3. **工具发现**：仅查询 send file 的一个匹配项，真实调用 `tool_search`，返回 `send_file_to_user`；没有发送文件或执行返回工具。
4. **数值与格式**：只用给定数字回答两行算式，得到 2% 和 1.9%，无工具调用或生产数据查询。

原始答案、调用及使用量见 `output/progressive-catalog-20261128/live-acceptance.json`。目录查询含发现后的下一次模型步骤，不能拿整轮累计输入直接与普通问答的单次输入比较。

当前技能搜索是词面匹配，不是语义检索。复杂意图可能需要换同义词、英文关键词或精确名称；专项任务首次使用也可能增加一次发现步骤。尚未做完整业务工具链和生产准确率验收，最终系统提示词全文快照的能力仍待后续补齐。
