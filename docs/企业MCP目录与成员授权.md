# 企业 MCP 目录与成员授权

本说明对应支持“企业 MCP”的 Octop 定制版。管理员统一发布连接定义和版本，各成员电脑自动同步；成员使用自己的业务身份授权，个人原有 MCP 配置继续保留。

这是功能使用说明，不代表安装包已发布、服务已部署，或其他 Windows 电脑已完成实际验收。实际可用性需按本文末尾的检查步骤确认。

## 先准备什么

- 企业授权中心和成员电脑都需要升级到支持企业 MCP 目录的版本。成员电脑只需先升级一次，后续目录修改通过同步下发；旧客户端不会因为管理员发布目录而自动获得这项功能。
- 成员使用同一企业的飞书身份登录或关联现有本机账号，并具有“使用已启用连接器”的权限。
- 管理员发布的 HTTPS MCP 地址必须能从各成员电脑访问。原来只在管理员 Mac 上运行的本机 SSH 隧道、脚本路径和回环地址不能直接供同事使用。
- 成员需另行取得对应业务系统的个人授权。飞书登录识别企业成员，不能代替售后质量或词元管理系统的业务权限。

## 管理员：保存草稿与发布

在**企业授权中心**登录管理员账号，打开“管理账号与权限”页面中的“企业 MCP 目录”页签。该目录在授权中心统一管理，不在成员电脑的“自定义 MCP”中编辑。

1. 点击“添加 MCP”，填写固定连接 ID、连接名称、HTTPS MCP 地址、成员授权方式和用途说明。
2. 按需要设置“目录中启用”和“可见成员”。可见成员从已完成企业飞书绑定的成员中选择；留空表示本企业全部成员。目录可见仍不等于具有业务数据权限。
3. 点击“保存草稿”。此时成员尚不会收到这次编辑。
4. 核对配置后点击“发布草稿”，产生一个新的已发布版本。成员电脑随后自动获取各自可见的条目。

目录只保存连接定义，不填写个人密码、访问令牌或远程执行命令。当前支持 HTTPS MCP 连接及“个人 MCP 令牌”“个人业务账号与密码”“无需额外凭据”三种方式。

发布后尽量保持“固定连接 ID”不变，以便保留成员授权及专家选择。更改目标地址或授权方式后，成员可能需要重新授权；客户端会提示并要求重新确认目标地址。

有未保存编辑时，先保存再发布或回滚。若提示目录已被其他管理员更新，当前编辑会保留；先整理需保留的编辑，再重新加载服务器草稿并合并。点击“重新加载草稿”会替换当前未保存内容。

### 停用、移除与回滚

- **临时停用：**关闭条目的“目录中启用”，保存草稿并发布。条目仍可见，但显示“已禁用”，成员不能将其作为可用工具调用。
- **移除条目：**从草稿移除连接，保存并发布。需要保留条目和便于恢复时，优先使用停用。
- **版本回滚：**在“已发布版本”中选择历史版本，点击“回滚并发布新版本”。系统将历史定义发布为一个新版本，保留原历史和已保存草稿；回滚不会覆盖尚未发布的草稿。

停用和回滚调整企业连接定义，不会把管理员的业务身份或密码发给成员。

## 成员：同步与本人授权

在本机 Octop 打开**“连接器 → 企业 MCP”**。这里显示本机目录版本、最近同步时间、管理员分配的连接及本人授权状态。

完成首次版本升级和企业飞书登录后，Octop 在运行且网络正常时约每 **30 秒**检查企业目录。页面在可见时每 **15 秒**刷新本机状态，所以管理员发布后，通常约一分钟内能在界面看到变化；这不是离线或异常网络下的送达保证。需要主动检查时点击“立即同步”。

若专家正在执行任务，新定义可能显示“待空闲应用”，将在任务结束后的安全时机切换，保留正在进行的工作。新授权已经验证但仍等待应用时，也会显示这个状态，无需反复授权。

### 首批两个业务连接

| 企业 MCP 条目 | 本次统一 HTTPS 入口 | 成员授权方式 | 成员需要准备 |
| --- | --- | --- | --- |
| 售后质量 | `https://120.79.0.171:18443/team-mcp/aftersales` | 个人 MCP 令牌（Bearer） | 由售后业务管理员明确为该成员签发的、范围受限的个人 MCP token |
| 词元管理 | `https://120.79.0.171:18443/team-mcp/workbench` | 个人业务账号与密码（Basic） | 成员本人的词元管理业务账号及密码，沿用业务系统的登录身份和权限 |

上表地址末尾不加斜杠，部署与验证状态以发布回执为准。后续具体地址以“企业 MCP”卡片展示的管理员发布 HTTPS 地址为准。不要把此前个人连接中的本机地址、SSH 私钥或脚本路径复制给同事，也不要共用管理员 token 或词元管理员账号。

**售后质量授权：**

1. 联系售后业务管理员，按实际工作范围取得本人专属、权限受限的 MCP token。令牌签发是业务系统的单独授权动作，加入飞书企业或看到目录不会自动签发。
2. 在“售后质量”卡片点击“授权”，核对弹窗中的目标地址。
3. 将令牌填入“本人 MCP 访问令牌”，点击“保存本机授权”。

**词元管理授权：**

1. 确认本人词元管理账号已开通，并具备所需查询范围；没有账号时由词元业务管理员按业务流程开通。
2. 在“词元管理”卡片点击“授权”，核对目标地址。
3. 填写本人的“业务账号”和“业务密码”，点击“保存本机授权”。

Octop 会先检查连接初始化与工具列表，验证通过后才加密保存本机凭据。密码或令牌不会进入企业目录，也不会在下次打开表单时回显。验证失败时可保留当前输入修正后重试；保存成功或授权目标变化时会清空输入。

“可用”表示当前定义对应的本人凭据已通过检查，不保证凭据永不过期或服务始终在线。业务权限和 MCP 只读范围由对应业务系统控制。

### 选择专家使用与移除授权

授权完成且连接可用后，成员自行在需要的专家或聊天 MCP 选择器中选用该连接。目录同步**不会自动为所有专家勾选工具**，也不会复制管理员的专家配置。

点击“更新本机授权”可更换自己的凭据。点击“移除本机授权”会删除当前成员在本机保存的授权，使该连接不能继续沿用旧工具缓存调用；它不会注销业务系统账号或撤销业务系统中已签发的令牌。需要彻底停用令牌时，仍需业务管理员在原系统撤销。

对于“无需额外凭据”的其他企业条目，点击“启用连接”可在本机启用，点击“断开本机连接”可保持本机断开；普通目录同步不会把主动断开的连接自动重新启用。首批售后质量和词元管理均需本人凭据。

## 保留哪些原配置

- 原“自定义 MCP”配置及其凭据继续保留，企业目录独立同步，不覆盖或合并个人条目。
- 既有专家、会话、项目文件夹和个人 CLI 配置保留在各自电脑；企业 MCP 发布不上传这些内容。
- 成员仍自行决定哪些专家使用企业连接。每人使用自己的业务身份，不会借用管理员或其他成员的业务授权。
- 若企业连接与既有配置发生冲突，界面会显示不可用及原因，应由管理员核对配置；不要通过删除个人配置来盲目排错。

## 状态与常见处理

| 页面状态 | 含义与处理 |
| --- | --- |
| 待授权 / 需重新授权 | 尚无匹配当前连接定义的有效本人授权，或目标已变化；核对地址后填写自己的业务凭据。 |
| 可用 | 本人凭据已通过当前连接检查，可以按需选择给专家使用。 |
| 已禁用 | 企业管理员停用了该定义，需由管理员恢复并发布；成员仍可移除本机授权。 |
| 待空闲应用 | 更新或新授权已收到，等待当前专家任务结束后应用。 |
| 目录同步失败 | 展示的是上次成功同步的目录，不代表最新版本；恢复网络后点击“立即同步”。 |
| 不可用 | 检查卡片显示的配置错误，联系管理员处理，不表示业务授权已经成功。 |
| 暂无分配给你的企业 MCP | 管理员尚未发布连接，或当前身份不在其可见范围内；请核对企业飞书身份和成员分配。 |

若授权弹窗提示目标变化，输入会被清空。先同步并重新确认地址，再打开授权；不要将同一密码直接提交给未经确认的新目标。

## 上线后如何确认

以下是待实际环境执行的验收步骤，不是已完成的验收结论：

1. 管理员发布一个版本，记录版本号；成员电脑在正常联网时自动出现同一版本及分配的条目，也可点击“立即同步”核对。
2. 成员分别用自己的售后 token、词元账号授权，并确认可用状态；使用无权限账号时，不应获得其他人的业务数据。
3. 在选定专家中手动选择企业 MCP，执行一项本人权限范围内的只读查询，核对实际工具调用、数据来源及权限范围。
4. 修改说明或停用条目并发布，确认其他电脑收到更新；专家忙碌时检查“待空闲应用”和任务结束后的状态变化。
5. 移除本机授权后确认该成员不能继续通过旧缓存工具调用；核对个人“自定义 MCP”和原专家配置仍保留。
