## 实现

`src/octop/infra/agents/middleware/response_policy.py` 在明确文字整理请求中追加短输出约束：逐句对应本轮材料与本轮实际取证，不借旧项目或召回记忆补写未经确认的范围、验证结论和承诺；默认一个可用版本；明确要求多个版本或解释时仍照做。完成、未完成、待确认以及抽样范围须保留。

只从当前用户指令选择提示，优先使用可见文本和同 ID 的原始用户消息，排除召回记忆及工具回包对提示选择的干扰。中文匹配限制在句首明确请求（允许礼貌前缀），防止“讨论如何把进展整理成三点”被当成直接改写；该边界已有单元及真实原生对话复核。代码、文件夹整理、创作、结构化输出和内部调度保留原有流程；不改写模型输出、不增加额外模型调用，不删改历史消息或改变项目目录。

这是一组保守的指令匹配规则，不是完整的语义分类器。复杂、隐含或非标准表达可能不触发，仍由通用回答规范处理；不能保证消除所有多余解释或事实扩写。

中英约束位于后端 `agents.response_rewrite_focus`，沿用语言解析和键对齐。源码、定制目录及本机安装仅涉及策略模块和两份语言包。

## 真实对话结果

在相同本机模型 `词元内置-2 / deepseek-flash` 上，新对话重跑原先五题，再追加三题，共 8 轮，未调用工具。基线与新对话并非完全相同的召回和上下文，因此只记录观察到的行为，不把差异全部归因于提示词，也不计算稳定通过率。

| 场景 | 观察结果 |
| --- | --- |
| 三点汇报 | 保留三项事实，不再声称映射和完整性已收口、不再邀请生成另一版。但仍补了“需明确后续处理方式”“再决定是否启动”，仅算部分改善。 |
| 通知改短 | 只给一个可用短句，保留截止时间和逾期后果，不附字数对比或改写说明。 |
| 固定100字的方案咨询 | 正常评估取舍，没有把咨询当成已生效设置；基线已正确，作为回归控制。 |
| 只回复收到 | 回复“收到。”，仅增加句号。若要求逐字符相等，不算完全一致。 |
| 切换到培训系统 | 聚焦审批链路盘点，没有带入游戏背景；理由仍较长。基线已正确，作为回归控制。 |
| 部署、反馈、效果状态 | 三点对应部署完成、反馈未汇总、效果未评估，没有补运行稳定或效果提升。 |
| 明确要求两个版本 | 给两个版本，两者均保留截止时间与逾期后果。 |
| 20条抽查 | 保留20条样本均通过与其余记录未检查，没有扩大成全量通过。 |

这8题是小规模虚构验证，追加三题也不是独立盲测；并未验证真实质量业务准确率、所有表达方式或长期多轮稳定性。汇报题的额外建议继续保留为未完全解决项，不能声称已消除事实扩写。

此次没有调用保存记忆工具，也没有修改 USER/MEMORY 文件；运行库原有的自动原始对话捕获仍存在，虚构题中的“不保存记忆”不能证明该基础设施已被禁用。本轮未改记忆机制。公开验收记录只保留虚构题、可见回答和用量，不导出私有推理或完整召回内容。

固定题目与检查要求见 `tests/evals/response_quality/focused_cases.json`。真实逐题记录位于 `output/response-focus-20261128/after.json` 和 `live-comparison.json`。最后句首边界修复后的两轮原生复核见 `final-boundary-live.json`：讨论整理方案时分析优缺点，直接改写通知时只交付一个版本，两轮均未调用工具。
