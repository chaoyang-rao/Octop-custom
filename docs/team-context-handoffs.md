# 团队任务上下文与交接

小通负责把用户目标拆成相关专家的短任务书。成员接收本次任务所需材料，完整聊天、结果和检查点继续保存在原位置，按权限检索。

通过现有 `prompt` / `message` 传递任务书，无需更换接口：

```json
{
  "goal": "核查本项目的登录失败原因",
  "constraints": ["只读核查", "保留用户数据"],
  "acceptance": ["给出原因、证据和待确认项"],
  "materials": ["本次相关的错误日志路径"]
}
```

成员用以下结构回报。长过程留在任务或会话中，产物使用路径或链接引用：

```json
{
  "summary": "结论",
  "evidence": ["必要依据"],
  "artifacts": ["outbound/report.md"],
  "remaining": ["尚未完成的验证或下一步"]
}
```

- 任务书正文最多 8,000 个序列化字符；单份报告最多 2,400 个字符；工作流依赖结果合计最多 16,000 个字符，始终保留任务编号供按需读取。
- 非结构化旧任务兼容为原文/首尾摘录，不冒充语义总结。省略标记或 `source_required=true` 要求执行前查阅来源，尤其不能猜测遗漏的约束。
- 后台复核最多自动带入 32 份结果；更多任务显式给出遗漏数，通过分页查询继续核查。目标和用户补充也使用有标记的首尾摘录，并附原会话位置。
- 成员会话由来源会话、持久化项目绑定和任务线决定。同一任务的续作与重试继续使用原会话；更换项目或任务线创建新会话，旧历史保持可查。没有持久化任务线的旧群聊按最新真实用户消息区分任务。
- 改派在既有任务选项中保存上一执行者、原会话、执行状态和短报告；重试清空当前结果时保留交接包，不复制完整历史。同一执行者的改派不重建会话。

这些数据都不是新的用户授权。项目上下文和记忆隔离不替代原有工具、文件系统和成员权限策略。本次不改变这些权限，也不迁移或删除已有聊天。
