# 团队回答结束后恢复发送状态

团队后台已经完成复核并记录 `ready / idle`，前端仍显示主持专家正在回答，发送按钮未恢复。

团队会保留 WebSocket 接收后续成员和协调复核结果。原来连接上的结束处理只执行一次；同一连接上的后续逻辑轮次虽然收到 `turn.ended`，也无法再次清除 `isStreaming`。另一个恢复分支在服务器报告主持人空闲时，会被成员仍在输出的消息阻止收口。

修复后，每个新的活动轮次都可以独立收口；重复结束帧保持幂等。服务器确认主持人空闲时恢复发送状态，成员正在输出的内容和监听连接继续保留。旧连接的迟到事件、审批暂停及中途追加仍由原有规则处理。

验证：

- 新增三条回归覆盖保留发送连接上的多轮复核、保留订阅连接上的多轮回答、主持人空闲但成员仍在输出。
- 上述测试先复现失败，修复后与既有团队流测试共 32 项通过。
- 当前安装版本源码上的聊天测试：105 个文件、693 项全部通过。
- TypeScript 项目检查、生产 Vite 构建、修改文件的 ESLint 与 Prettier 检查通过。
- 全站前端测试为 319 个文件通过，另有 8 个原有失败文件（5 条失败断言及 3 个加载失败的测试套件）；已在没有本次修改的 `2f0eb0fc` 源码上复现同样失败。涉及 PDF 的 DOMMatrix 测试环境、侧栏旧断言及知识库/发布专家/模型设置旧测试，未修改这些无关功能。
