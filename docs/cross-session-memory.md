# 按项目共享的跨会话记忆

聊天标题右侧「更多 → 跨会话记忆」可查看、搜索、添加、纠正或停用记忆。
手机聊天顶部提供同名入口。来源链接打开原始会话；「修改记录」保留纠正前后的内容。
原有专家记忆页继续展示旧库，不会自动把未分类历史搬入某个项目。

## 范围

| 范围 | 默认读取 / 写入方式 |
| --- | --- |
| 用户 | 同一账号的专家共用；仅显式保存通用偏好，不从所有聊天无差别汇总。 |
| 项目 | 同账号、同一已绑定项目文件夹的专家私聊与团队群聊共用。绑定项目时的默认持久记忆。 |
| 专家 | 当前用户与当前专家独立的经验；未绑定项目时默认使用。项目内可显式检索通用专家经验。 |
| 会话 | 当前会话的临时记录，其他会话不会自动读取。 |

项目身份使用账号和数据库中的规范项目路径，独立于项目名称、模型选择、任务 worktree。
新建的任务会话和任务群继承来源会话的项目；已有归属不被覆盖。
小通和成员通过实际会话归属及团队成员资格获得访问权。共享专家按使用者隔离，不能读取所有者旧库。

## 事实、来源和纠错

自动捕获与提炼只接收用户陈述。专家回复、派工背景、工具结果继续保留在原始会话历史中，
不会仅因为专家说过就变成已确认的长期事实。需要保留的专家结论可由用户在面板中确认添加。

`memory_save` 要求来自本轮用户消息的精确引文，保存内容必须是引文的原文片段。
`scope` 指定范围，默认当前项目 / 当前专家；`replaces` 指定同范围的旧 atom ID，可用于明确纠正。
存储沿用 octop-memory 的 RawEvent → Candidate → Atom、替代关系及只追加的 journal。
旧结论标记失效，不删除原始证据。界面纠错需携带读取时的范围 token；项目归属变化后拒绝旧界面写入。

自动召回只读取本会话、用户偏好以及当前项目（或未绑定时的专家范围），合计最多 6000 字符。
已绑定项目时，旧库只通过显式 `memory_search(scope="legacy")` 或原有专家记忆页面查看。
未分组的私有专家会话保留对本人旧专家记忆的检索，作为「未分类历史」参考，不迁入项目库；共享专家禁止此回退。
历史中的召回快照保持可追溯，但 scoped 请求只重放最新用户回合、同范围的快照，
避免旧项目或已纠正的旧召回反复进入上下文。计量与实际重放使用同一规则。

## 存储和兼容

- Octop 管理账号、项目绑定和权限；octop-harness 组装范围服务；octop-memory 负责原有存储、检索、提炼、纠错。
- SQLite 范围库位于 `OCTOP_HOME/shared-memory/`，命名空间只包含稳定哈希。PostgreSQL 沿用控制面的 DSN，以独立命名空间隔离。
- 原专家记忆库、会话检查点及原始聊天记录均保留，不做破坏性迁移；原有记忆导出/恢复入口仍针对旧专家库。
- 关闭专家记忆时不创建范围服务。没有真实用户/会话身份时拒绝访问，不回退到旧专家库。
- 每次后台捕获固定使用发起时的范围；不会用进程级可变的「当前项目」路由异步写入。
- 本轮不增加外部记忆服务，不回填或自动分类已有历史，不改变账号、模型、CLI 和头像配置。

## 验证

`uv run pytest tests/unit/agents/test_memory_scopes.py -q` 验证临时真实 SQLite 下的同项目跨专家/群聊共享、
跨用户/项目隔离、原始来源、纠错留痕、停用、HTTP 权限、范围变更保护和任务项目继承。

`PYTHONPATH=src:customization/packages uv run --no-sync python -m unittest customization.tests.test_scoped_memory_runtime`
使用离线模型验证完整 graph 中的自动捕获和召回、旧库隔离、配置 callback 不可反序列化以及记忆计量。
前端回归验证来源跳转、按读取范围纠错、跨会话迟到响应丢弃及服务不可用时禁止写入。
