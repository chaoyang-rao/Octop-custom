# 桌面更新根地址验收修复

真实安装记录显示，112804到112809的更新包已完整下载并完成程序/数据备份，随后回滚。回滚后本机健康检查为112804，2个账号、17个专家加载。隔离验证中，112809自带启动器在空白目录和旧控制库只读快照的pending模式都能启动；没有发现缺失的控制库列。

## 根因与修复

`desktop/src/process.go` 的 `dashboardURL` 返回 `http://127.0.0.1:<port>/`。桌面壳把它原样保存为候选健康地址，而更新助手要求解析后的path为空；末尾的 `/` 会被拒绝，直接拼接健康端点还会得到双斜杠。因此正常的新程序也会被判为未通过验收并回滚。

1. 新桌面壳在写候选日志前去掉一个末尾斜杠，使已经部署的旧助手也能接受新候选。
2. 助手在校验和请求前进行相同规范化，兼容现有发送方；保留本机地址、端口、路径、查询及版本/pending校验。
3. 回归测试覆盖两个产品的规范根地址、带尾斜杠根地址、其他路径和查询。旧实现两项尾斜杠场景失败；修复后更新助手测试和 `go test ./...` 通过。

112809的企业后续通知已撤回，旧GitHub附件不替换。修复版使用112810 / Dora0.10.11，沿用现有签名、公钥和成员权限。

## 验收顺序

通过完整发行门禁后，先仅向本机原账号提供修复版，使用其实际112804旧助手完成一次正常升级；确认安装日志进入accepted、新版本启动、原账号/专家/聊天保留后，再恢复原有授权更新范围。相同版本只调整范围时继续使用相同包与摘要，不重打或替换附件。

未将日志回滚或安装包检查当作真实升级成功；未直接恢复旧数据库，也不把新版本包公开等同于全员电脑已安装。
