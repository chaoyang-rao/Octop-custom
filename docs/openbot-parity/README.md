# 用户能力对齐记录

参照版本固定为 [OpenBot 1cd8906](https://github.com/nightly-labs/openbot/tree/1cd89066662bda7daf641a93af5e464c5cbc8b9a)。用户已选择依据公开功能和官方接口独立实现，覆盖全部用户功能（含移动及远程），运营后台单列。原项目采用非商业许可，本目录没有引入其实现代码、图标、技能文本或原文说明。

[运营后台单列](operations.md)。[机器可读覆盖表](coverage.json) 记录每项范围、现有代码、待补能力及验证状态。`present_needs_validation` 只是发现现有实现；`implemented_pending_validation` 只是已接线，均不代表验收完成。只有实际验证后的项才使用 `verified`。需要服务商账号、商店签名或推送资源的部分单独记录，不能用演示或名称占位代替。

应用目录包含公开版本的 30 组服务名称；对应连接参数优先依据服务商当前官方文档重建，使用 Octop 的账号隔离、凭据加密和 MCP/OAuth 机制。更新时须同时检查端点、认证方式、可用平台及真实工具发现。连接器配置和工具调用需由用户实际授权后验证。

## 已落地的首批改动

- 应用目录从 29 项扩展至 58 项，保留原有 29 项与配置逻辑，新增预设走真实 MCP HTTP 或本地进程；密钥通过请求头或进程环境传递。第三方本地 MCP 包固定为核对过许可的版本。
- 新预设的 OAuth 从资源端发现授权服务器，令牌交换及刷新保存该服务器和资源信息；不冒用其他已批准客户端。需要服务商注册或桌面客户端的项仍记录外部依赖。
- 不支持当前主机的本地预设会显示说明并禁用连接，后端同样拒绝启动。
- Slack Socket Mode 通道、名单限制、话题会话与附件收发已实现，详见 [使用说明](../slack-channel.md)。Slack 用户账号工具连接仍需继续补齐，通道上线不等于全部 Slack 能力完成。
- 真实只读发现：Aave 56、Hugging Face 4、Context7 2 个工具。只执行协议初始化与工具列表读取，没有运行工具、访问私人账号或提交交易。其余需要账号的连接不能仅凭 HTTP 状态记为验收通过。

本轮仅准备源码和 `avatars-v20` 定制程序快照；尚未安装到正在使用的 Octop。任务工作流、移动及远程访问、密码库等其余缺项继续按覆盖表推进。全量源码和三平台检查交由 GitHub Actions 执行，本机执行有界回归，沿用 8 GB 主机的既有资源约束。
