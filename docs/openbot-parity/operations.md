# 单列：云服务运营后台

用户确认本轮先对齐全部用户能力（包含移动和远程访问），平台运营另列。本文件区分用户在 Octop 中使用连接器与经营自己的云服务；它不表示运营后台已完成。

| 范围 | 已有基础 | 另立实施与验收范围 |
| --- | --- | --- |
| 账号与身份运营 | Octop 本地用户、角色、邀请与 SSO | 若提供统一云账号，需自有身份域名、邮件渠道、账号恢复和跨服务器身份策略 |
| 订阅与收费 | 用户可连接自己的 Stripe 账号使用其工具 | 平台自身套餐、订单、订阅变更、退款、发票和收款对账；需要自己的商户账号与规则 |
| 托管资源 | Octop 自托管、Bridge、多服务器客户端、TLS 及远程配置 | 面向客户的服务器创建、隔离、扩缩容、生命周期与成本归属；需要自己的云资源 |
| 额度与用量运营 | 现有 Token Usage、模型与权限管理 | 套餐权益、额度发放、限额及计费用量对账，须与实际供应商数据核对 |
| 安全与服务运营 | 现有管理、安全和审计能力 | 客户支持、服务告警、事故处置、备份恢复与数据保留制度 |
| 官网与增长 | 与核心用户工作流独立 | 自有品牌站点、注册引导、运营邮件与活动配置 |

实现路线仍为依据公开行为与官方接口独立开发。不调用 OpenBot 的私有账号、收费或托管后台，不复制其运营实现，不把配置一个支付连接器当成平台计费系统。

这一部分需要先明确经营主体、云部署与收费规则，再形成单独可审查的交付范围；当前没有为此创建商户、购买资源、发信或向用户收费。
