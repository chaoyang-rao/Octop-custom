# 企业专家与 Skill 统一分发

管理员在企业授权中心发布专家提示词、Skill 文件和版本；各成员电脑主动拉取各自可见的内容，在相关专家空闲时应用。每位成员持有独立副本。此功能须先安装支持它的客户端一次，旧版不会因为发布目录而自动新增软件能力。

## 管理员如何发布

1. 在成员桌面端的「专家 → 企业专家与 Skill」页面，选择自己拥有的专家或 Skill，点击「下载资源包」。专家仅导出受管提示词文件，不导出 USER.md、聊天、记忆、CLI、项目目录、模型或凭据。Skill 导出完整相对文件树，含脚本、资料和二进制资源。含私密路径的资源会被拒绝，请先清理发布副本。
2. 在企业授权中心的「企业专家与 Skill」页签导入资源包，也可以直接新增并编辑。审核文本和脚本，避免将密钥写在普通正文或代码里。系统不会从任意文本中识别所有嵌入式秘密。
3. 为资源设置稳定 ID、名称、说明、可见成员及启用状态。未来更新使用同一 ID。同一 ID 的专家/Skill 类型不可互换。
4. 专家可以关联已加入草稿的企业 Skill 和企业 MCP。只下发资源引用，不复制个人授权。依赖 Skill 必须启用且对专家的全部目标成员可见；成员还需具有对应模块权限。
5. 「保存草稿」只保存，点击「发布给成员」才生成新的不可变版本。多管理员并发修改使用版本校验，旧编辑不会覆盖新草稿。
6. 历史回滚会把选中历史重新发布为更高版本，不删历史、不替换未发布草稿，也不跳过成员的本地冲突检查。

专家分发范围为 SOUL.md、AGENTS.md、IDENTITY.md、TOOLS.md、HEARTBEAT.md、PROACTIVE.md，以及名称、说明、显式头像和企业依赖引用。未指定头像时保留本地随机或个人头像。个人模型、CLI、工作区后端和项目路径不分发。首批企业 MCP 仍沿用「售后质量」「词元管理」目录与各成员各自授权。

## 成员端如何更新

- 使用企业飞书身份登录已升级的客户端，保持联网。后台约每 30 秒拉取目录；已下载且待空闲的内容会继续重试。
- 新资源创建新的独立专家或私有 Skill 包，带短标识区分，不会按同名覆盖原有专家和 Skill。原有聊天、记忆、个人配置和授权仍保留。
- 普通更新只改受管内容。个人单独新增的文件、个人配置和只在本地发生的改动继续保留。双方都修改同一文件或受管字段时，整份资源暂停应用，不会先替换其中一半。
- 「专家 → 企业专家与 Skill」显示版本、待空闲、含本地修改、冲突、失败或暂停状态。存在冲突时，主界面也会显示提示。
- 打开冲突对照，逐项选「保留本地」或「采用管理员新版」。确认时再次核对本地内容、权限和管理员版本；如果发生变化，会要求重新比较，不沿用旧选择。
- 保留本地会把本次远端版本记为新基线；后续远端没有再修改该项时，不反复询问。远端再次修改它时会重新比较。
- 可暂停单个资源的自动更新，并保留本地副本。恢复后继续进行版本及冲突检查。
- 关联企业 MCP 只有在成员自己的授权可用时才挂载；模板不会借用管理员或其他成员的凭据。

## 数据与故障边界

受管修改前保存备份和恢复日志。写入或运行时重载失败会恢复旧受管内容；进程中断后重试恢复时，只撤回该次更新写入的字节，不撤回之后产生的个人编辑。已有会话和记忆不参与资源版本替换。Skill 更新会等待所有挂载它的专家空闲。

管理员停用、移除或缩小可见范围，会停止后续资源分发，保留已下载的成员本地副本和个人数据。内容分发不是远程删除或远程执行控制；业务访问权限仍由企业权限及各 MCP 业务系统控制。离线设备恢复联网后再获取变化。

外部编辑器直接改文件不经过应用的编辑锁。更新会在写前核对内容；为避免外部编辑与更新同时发生，进行大幅本地编辑前可先暂停该资源的自动更新。

## 验收

- 两个隔离节点使用不同公司成员身份拉取同一版本，生成不同副本；一个成员的本地编辑不影响另一个。
- 更新期间的聊天记录、记忆文件、CLI/模型配置和个人凭据保持不变。
- 专家工作时只显示待应用；空闲后再加载。Skill 等待所有挂载专家。
- 本地及远端同时修改同一文件时，保留本地并提示；过期对照票据被拒绝。保留本地及采用新版两种选择分别验证。
- 验证重载失败回退、进程中断恢复、依赖可见范围、设备凭据只读范围，以及被拒绝输入不回显秘密。

测试与实际部署/安装包发布回执分别记录；隔离节点测试不等于已在同事的 Windows 实机登录验收。
