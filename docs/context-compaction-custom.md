# 定制版上下文压缩修复

本次修复沿用 Octop 与独立运行库的边界：压缩、预算和模型中间件顺序在冻结的 `octop-harness` 源码中维护；团队授权、会话引用和用量展示在 Octop 中维护。

## 行为

- 每次实际模型调用使用独立的输入预算，扣除配置的输出预留；共享 SDK 客户端的 profile 不再被请求改写。自动回退重新经过目标模型的压缩检查，最后一道检查覆盖实际发出的系统提示、工具和消息。无法容纳输入时保留原路由及上下文；未登记容量的模型不作为已验证安全的回退候选。原有默认模型、个人偏好和手动选择规则保持不变。
- 先将较大的旧工具结果投影为可检索文件引用，工具调用与结果 ID 保持对应，原始消息保留。需要摘要时按实际窗口分块覆盖整个选定区间，并携带上一块检查点。摘要失败不再写入成功占位文字。
- 新摘要标记 `coverage_version=2`。旧摘要缺少覆盖标记且原始区间仍完整存在时，下次调用或手动压缩会从原始记录重建；只在成功后提交新状态。独立会话不合并。
- 团队派工背景只在本次模型请求中注入，不追加到成员消息列表。已在有效上下文中的群消息按消息 ID 去重；只折叠完全相同的旧背景，独有约定保留。引用其他专家发言时标明作者，同时保持消息位置、工具配对和原始界面记录。
- 用量快照绑定实际专家和会话，群聊不采用成员流中的用量提示。重启后优先读取有版本与归属标记的小型消息元数据；不解码巨型会话检查点。账本回退标为估算，容量未配置时显示未知。

## 验证与分发

回归覆盖完整旧历史、摘要失败、旧摘要重建、两群并发、较小模型回退、原始工具结果与作者信息、审批恢复及圆环容量切换。测试使用离线模型，并用本机便携 Python 与实际依赖执行独立回归，不消耗真实模型额度。

后端修改后运行 `scripts/custom/sync_octop_source.py --apply`，前端构建后运行 `scripts/custom/sync_dashboard.py --apply`。`customization/packages/` 是可恢复的实际分发源码；本次不修改账号、模型配置、工作区或数据库结构。

运行库改动位于 `customization/packages/octop_harness/`；对应独立回归为 `customization/tests/test_context_compaction.py`。加载新 Python 模块与新界面需要重启 Octop，执行前应确认专家空闲且输入已保存。
