# 飞书统一登录，任务在各自电脑执行

Octop 定制版支持独立的企业授权中心和桌面节点。默认仍为个人模式；只有明确配置中心地址的客户端才启用企业登录。

授权中心保存飞书身份、角色权限及可撤销的设备授权。模型、项目、专家、聊天和 CLI 凭据保存在各自电脑。中心不提供专家执行、文件、终端、浏览器控制或 Bridge 接口，不接收桌面文件和会话。

## 管理员首次配置

1. 在独立的非 root 系统账号下运行 Octop，配置 `enterprise_center_enabled: true`，后端仅监听 `127.0.0.1`，由 Nginx 提供有效 HTTPS。
2. 通过受保护的初始化入口创建管理员。若关闭 `require_setup_password`，必须同时阻止公网访问 `/api/setup/` 写接口，仅允许 SSH 本机转发初始化。不要直接向公网开放无密码的初始化接口。
3. 打开 `/enterprise/admin`，在“飞书”页配置企业自建应用的 App ID、App Secret。Secret 只填写在服务端的 HTTPS 管理界面；不要写入安装包或 Git。
4. 在飞书开放平台为应用启用网页登录，将界面显示的 `/api/auth/oauth/callback` 完整 URL 加入重定向地址，并配置仅本企业同事的应用可用范围，然后发布应用。
5. 以刚创建的本地管理员登录中心，在 `/enterprise/approve` 点击“关联企业飞书”。这次绑定将企业 tenant 固定下来。普通同事无法抢先绑定其他企业，其他企业身份会被拒绝。更换 App ID 后需要重新验证飞书身份。
6. 同事登录后，在用户、角色和分组页面维护功能权限。停用账号会使其设备授权失效，也可撤销单个设备。离职及部门变更目前需要管理员操作，不包含通讯录自动同步。

示例中心配置（独立数据目录，目录权限 0700）：

```json
{
  "enterprise_center_enabled": true,
  "require_setup_password": true,
  "bind_host": "127.0.0.1",
  "port": 18088,
  "default_timezone": "Asia/Shanghai",
  "database": {"driver": "sqlite", "sqlite_path": "octop.db"}
}
```

## 同事使用

企业便携包可只预置公开的中心地址：

```bash
python scripts/custom/build_portable.py --platform darwin-arm64 --output dist \
  --enterprise-authority-url https://login.example.com
```

Windows 为 `windows-amd64`，Intel Mac 为 `darwin-amd64`。GitHub 的 Custom release 工作流也提供同名可选输入。留空仍构建个人版。无需把 App Secret 或管理员账号分发给同事。

已有安装也可通过 `OCTOP_ENTERPRISE_AUTHORITY_URL` 或独立 `config.json` 的 `enterprise_authority_url` 指定中心。节点必须监听本机回环地址。先保存草稿、等待当前任务结束并备份数据，再重启切换模式。

登录时，本机显示短设备码；打开企业中心，以飞书身份登录，核对电脑名称后确认授权。本机后台交换设备凭据，不把它放入浏览器、地址栏或日志。

沿用旧个人数据时，先点击“验证本机账号”，完成原账号的密码及 MFA 验证，再选择沿用本机账号。授权后会再次显示公司身份和本机账号，确认后才关联。原本地 user id、专家、项目和聊天不变；企业权限不覆盖原个人账号在数据库中的角色与权限。不选择关联时创建独立的本地企业身份，不自动合并其他人的数据。

首次授权成功后，中心地址会保存到本机配置，保留其他配置项。以后安装未预置企业地址的新版时，仍沿用已确认的企业登录设置；退出登录也不会关闭企业模式。

## 权限生效和恢复

- 界面权限最多缓存 30 秒，网络失败后拒绝新的受保护操作。WebSocket 会在收发消息及空闲检查时刷新，权限变化或撤权后关闭连接。
- 每次启动专家任务或恢复人工确认任务都直接向中心核验。既有任务不会因断网被强制终止，避免在写文件过程中中断。
- 企业角色不映射成本机管理员，即使中心管理员登录桌面，也以公司授予的功能权限运行。
- 退出会删除本机加密设备凭据；中心暂不可达时也能退出。重新登录会撤销旧设备凭据。
- 恢复个人模式时，使用未预置企业地址的个人版，移除配置和环境变量中的企业地址后重启，保留原数据库和数据目录。旧个人账号的原权限仍在。先备份再切换，不要用空目录覆盖已有数据。

本地操作系统和文件所有者仍能管理自己的程序与文件；本功能面向企业登录、产品内权限和设备授权，不是远程控制或操作系统管理工具。

功能权限沿用 Octop 原有的页面和配置权限，不是对智能体工具的细粒度白名单。需要同事自行填写模型密钥时，可授予“模型 > 云端”权限；终端等功能按需授予。禁止账号继续启动任务时，应停用账号或撤销设备授权。

## 验证范围

自动测试覆盖企业隔离、管理员首次绑定、设备码用途隔离、一次性交换、旧账号确认关联、凭据加密、权限变化、停用及撤销、新任务检查、WebSocket 首帧认证与连接撤权、退出并发及离线失败。真实飞书 OAuth 仍需要在实际企业应用配置后完成一轮管理员绑定和同事登录验收。

飞书官方的 [Web 登录接入示例](https://open.feishu.cn/community/articles/7317091221654224898) 包含 IP 和端口形式的回调地址。无域名时可使用有效的 IP HTTPS 证书；实际可用性还需按应用后台的回调地址校验和真实 OAuth 登录验证。
