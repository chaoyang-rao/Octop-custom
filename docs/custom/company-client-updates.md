# 企业统一客户端升级

适用 `1.0.3b3.post2026111801` 起的 Windows x64、Intel Mac 与 Apple 芯片 Mac Octop 主程序。

管理员从定制仓库选择完整 Release，导入草稿并发布给全部或指定成员。企业中心只签署和下发受限的版本清单；客户端每约 30 秒主动检查，普通成员可更新自己的程序，设备令牌不能发布版本。清单及升级包不含聊天、记忆、业务凭据或任意远程命令。

客户端验证预置的企业 Ed25519 公钥、版本、平台、仓库地址、大小与 SHA-256。先下载，安装前重新校验成员权限和发布状态，确认所有本机任务、ACP 与审批空闲，再取得全局执行预留，阻止更新期间开始新工作。

原生桌面壳将已批准的本地作业交给独立 Go helper；helper 先停止本机后端并备份程序与本地用户数据，再退出桌面壳，替换三平台对应的完整程序包。新程序在提交确认前不对外提供用户工作入口，安装或核心启动失败时由 helper 恢复上一程序和升级前快照；成功后恢复消息通道、计划任务与资源同步。备份留在本机，不分发或上传。

初次引导版采用 Windows 用户级安装，以便成员更新自己的程序。不可写的安装位置和外部 PostgreSQL 数据库不执行自动替换，使用受校验的安装包处理。升级不对外部项目目录或业务系统执行回滚。

`0901` 等旧客户端没有此协议，必须先安装一次带通道的新版本。之后 MCP、专家、Skill 和客户端程序分别沿各自通道更新。

发布前验证包括签名与撤销、权限隔离、下载完整性、任务预留、备份恢复、候选启动失败回滚和三平台原生打包。首次发行使用新不可变 Release，不替换历史附件；角色图包继续只在内部授权组件中分发。

## 管理员发布

1. 用超级管理员飞书账号进入[客户端更新管理](https://120.79.0.171:18443/enterprise/admin?tab=client-updates)。
2. 点“检查完整发行版”，选择版本后“导入草稿”。只有三平台自动更新包和 GitHub SHA-256 信息齐全的已发布 Release 才能导入，草稿发行不出现在列表。
3. “更新范围”留空即全部已授权成员，也可选择指定成员先试用。点“发布更新”后，在线客户端约 30 秒内检查到更新。离线电脑下次打开联网后接收。
4. 设备列表显示成员、设备平台、当前/目标版本、进度和最近检查时间。“撤回通知”阻止后续下载和安装；已进入本机替换阶段的安装会完成或回滚，不远程中断。

## 成员更新

收到通知后点“查看更新”，保存草稿、完成所有专家任务与审批，再点“下载并安装”。安装过程会重启 Octop。也可从设置的更新页点“检查企业更新”。更新失败可重试；升级前的用户数据快照保留在本机 `.octop/client-updates/jobs/<作业编号>/backup`，已有 `.octop/backups` 也保留。

旧版首次升级：从[111801 发布页](https://github.com/chaoyang-rao/Octop-custom/releases/tag/custom-1.0.3b3-20261118.1)下载对应 desktop 安装包并退出旧 Octop 后安装。Windows 新版是当前用户安装，后续从新版创建的“Octop Custom”快捷方式启动；不要继续点击旧 Program Files 内的快捷方式。Mac 替换原 OctopCustom.app。不要卸载或删除 `.octop` 数据目录。

企业更新签名私钥只保存在授权中心加密的 secrets 表，公开安装包仅包含公钥。更换签名公钥需要先发行包含新公钥的引导版本；不会从网络自动信任未知签名者。主程序安装包与桌宠角色素材分别发行。
