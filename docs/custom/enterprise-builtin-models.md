# 企业内置词元模型

Octop 定制版与独立 Mac 桌宠“哆啦”共用企业模型服务。同一飞书企业的有效成员获得专家权限后，正常登录即可自动配置词元模型，无需填写共享模型密钥。默认使用 `deepseek-v4-pro`，实际可用模型以授权中心发布的启用列表为准。

## 成员使用

1. 从本仓库安装定制版 Octop，或安装独立哆啦。
2. 通过企业飞书登录，沿用原有本机账号。
3. 打开聊天中的模型列表，查看自动配置的“词元内置”连接；哆啦显示“哆啦内置”。新专家默认使用企业模型。
4. 已有个人模型连接、专家明确选择的个人模型和聊天数据保留。可以继续使用个人连接。

内置模型连接的配置由企业管理，本机显示的占位密钥不可导出上游主密钥。每台机器只保存当前成员自己的企业设备授权；撤销设备、停用企业身份或收回专家权限后，新模型请求会被拒绝。企业模型服务关闭时，不会自动切到个人账户产生费用。

MCP 的售后质量令牌、词元工作台账号仍需成员分别完成个人授权。模型可以使用不表示业务 MCP 已获授权。专家和 Skill 沿用企业目录更新，保留各自聊天、记忆、个人授权与本地修改，出现冲突时提示。

## 管理员设置

在企业授权中心的“企业词元模型服务”中设置服务开关、模型来源、默认模型、输出上限、每分钟请求数和成员并发数。服务端保管并加密上游凭据，成员只获得公开模型元数据。用量按成员记录，沿用现有 Token 额度校验。

模型请求经企业服务器转发到词元 API。授权中心记录模型、Token 和估算用量标记，不写入聊天正文；成员本机继续保存聊天历史。上游模型 API 仍会收到完成推理所需的请求内容。

哆啦开放专家的名单独立管理，不影响 Octop 主程序的企业模型服务。未配置知识库时，哆啦保留后续接入口，可先基于当前提供的文字或图片提问；识图和生图取决于实际模型及服务配置。

## 构建与数据边界

主程序的 Windows、Mac Intel 和 M 芯片安装包使用 `custom-release.yml`。独立哆啦使用 `dora-macos-package.yml`，生成同时包含 Intel 和 M 芯片引擎的通用 Mac 安装包。

安装包只包含程序、固定运行时和公共企业登录地址，不包含模型主密钥、个人设备授权、MCP 凭据、聊天数据库或个人知识库。哆啦角色素材的来源与单独权利说明见 `desktop-companion/README.md` 和包内 `ASSET-NOTICE.txt`。

## 无密码 MCP 账号选择

“管理本人授权”会显示当前飞书身份已验证关联的业务账号。词元工作台按 Feishu union identity 精确匹配现有启用账号，不按姓名猜测，不重置原密码；选择后生成仅可用于只读 MCP 的委托凭据。真实网页登录会话只保留在服务器，客户端不获得工作台会话 Cookie。

售后 MCP 需要独立的业务账号绑定，默认不授权。既有业务所有者可由服务器管理员显式绑定；其他成员不会因为是本机管理员或公司管理员就自动取得售后所有者权限。旧的个人令牌和密码授权入口仍可使用，其他成员原授权不变。

服务器部署脚本位于 `scripts/enterprise_mcp/`，只针对经过哈希核对的既有网关进行增量安装。`install_account_auth.py` 默认不建立售后所有者绑定；仅在已核实该成员就是业务所有者时使用显式参数 `--quality-owner-user-id`。绑定策略保存在服务器私有目录，不进入源码和安装包。
