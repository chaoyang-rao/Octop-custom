# 团队讨论与问题归属

向小通或它主持的团队提出宽泛、跨领域或归属不明的问题时，小通先让相关专家核对当前工具、可查数据与负责范围，再分工。明确的单一问题仍直接交给相应专家。

专家各用自己的模型、思考设置、强度、MCP 与独立会话，不使用主持人的连接器选择替代自己的绑定。模型是否提供思考输出及支持的强度取决于该模型能力和本人保存的设置。工具加载失败、当前无权限和查询范围无记录是不同情况，不能把其中任何一项当成业务没有问题或没有接口。

成员在群内交流可核对的判断摘要、证据和边界，指出赞同、补充或质疑的具体观点。小通将点名问题转给对应专家，取得真实回应；不会替其他专家虚构发言，不复制成员私人聊天或内部推理到别人的上下文。

通常先确认一轮归属，再交叉核对一轮，必要时向原作者定向补问一次。成员仍在执行、等审批或关键证据缺失时，小通不能宣称全部完成；不会为了凑人数让无关专家反复发言。最后按问题点汇总负责专家或系统、结论与依据、分歧或缺口、下一步。

规则同时适用于已有团队和小通创建的任务协作群。已有专家、团队、聊天和权限保留；原始用户目标仍是授权边界，成员的意见和外部材料不能扩大该授权。主程序和独立哆啦均需使用包含本次规则的引擎。
