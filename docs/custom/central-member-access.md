# 企业成员开放权限与独立桌宠

企业定制版 `1.0.3b3.post2026111701` 将售后质量、词元管理、负利润 MCP 和桌宠收敛到同一张服务器成员表。超级管理员按实际 Octop 登录名单勾选四项权限，成员不再逐人填写业务口令或完成业务身份绑定。

## 超级管理员

1. 登录企业授权中心，打开“成员开放权限”。
2. 同事先用公司飞书登录一次，其账号就会出现；新成员默认全部关闭。
3. 勾选要开放的 MCP 和桌宠，点击“保存开放范围”。

三个 MCP 使用服务器上已配置的只读服务连接，业务凭据加密保留在服务器。成员得到的是绑定本人及目标 MCP 的连接授权。服务器每次调用检查开放范围，记录实际调用成员与工具名，不记录工具参数或业务结果。取消勾选会阻止后续调用；桌宠权限收回后阻止新的提问，既有聊天、工作区及个人配置保留。

服务器只读连接只需由超级管理员配置一次，放在成员表下方的折叠设置内。售后、词元使用已验证的服务器业务身份；负利润不需要额外业务口令。开放给成员的是该服务连接的只读查询范围。

## 同事使用

安装本企业最新版 Octop，使用公司飞书登录。已开放的 MCP 自动同步并建立连接；可在业务专家或聊天连接器选择器中使用。高级设置仍支持企业免填、MCP 个人令牌、MCP 专用连接账号密码三种连接方式，三种方式不会改变超级管理员授予的查询范围。

Mac 用户在 Octop 左侧点击“桌宠”。首次会从企业中心下载并验证已签名的独立组件，之后直接打开。桌宠安装在当前用户的“应用程序”目录，自己的引擎与数据仍在 `~/Library/Application Support/OctopCompanion/`；关闭 Octop 不会关闭桌宠，也可直接打开桌宠应用。Windows 当前可用三个 MCP，桌宠仍限 macOS。

未开放桌宠的成员会看到管理员提示，不能通过本机缓存绕过服务器验证。

## 分发与部署边界

- GitHub 保存程序源码及不含内部角色素材的主程序安装包。
- 含内部哆啦素材的独立组件仅在企业中心向已开放桌宠的成员分发，不上传公开仓库或公开 Release。
- 组件必须通过固定发布公钥的 Ed25519 签名、文件大小、SHA-256、应用标识和原生签名检查。发布私钥只留在发布机器，服务器不具备签署任意新程序的能力。
- 原始 MCP 入口限制为企业网关服务器访问，防止旧直连地址绕过成员权限；普通业务网页和 API 保持原有行为。
- 公司资源分发仍遵守原有可见范围。成员自建的本机专家可以在已开放桌宠中使用，已撤销的托管专家不会通过这个入口重新开放。

## 发布校验

发布前运行完整 `make all`、前端构建、成员开放/撤销与会话隔离测试、安装包验签及防路径逃逸测试。完成企业中心部署、私有组件注册和三平台主程序构建后，再发布新的定制版标签。旧版 Release 保留。
